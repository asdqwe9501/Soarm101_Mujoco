# Plan 5: 지름길 방지 데이터셋 (사용자 설계 원칙 반영)

**배경:**
- sft_v3는 장면에 따라 같은 잘못된 색을 고정적으로 고른다.
- 사용자가 제시한 지름길 방지 원칙 세 가지를 수집에 반영한다(2026-10-13).
  1. 위치와 순서 무작위화
  2. 조명과 배경 다양화
  3. 네거티브 샘플링

**목표:** 300개(배치 100개 × 명령 3종)를 수집한다. 기존 1,200개와 합쳐 sft_v3에서 30k 스텝 이어서 학습한다. 반사실 시험에서 맞는 공 첫 시도 95%를 노린다.

## Global Constraints

- 데이터셋 형식, 키, 단위, 명령문 틀, 성공 판정은 기존과 같다.
- 정답 행동(라벨)은 언제나 "현재 상태에서 **명령한 색** 공을 향한 올바른 행동"이다. 일부러 잘못 가는 실행 경로를 라벨로 쓰지 않는다(DART 원칙).
- 무작위화는 옵션으로 켠다. 기본값(끔)일 때 기존 동작과 테스트는 그대로여야 한다. 단, 색-위치 무작위 배정은 항상 적용한다(치우침 수정).
- 공 색이 서로 구분 가능해야 한다. 공 색 변화는 작게(각 채널 ±0.05 이하) 한다.

## Task 1: 장면과 시각 무작위화 (`sim/env.py`)

- **색-위치 무작위 배정** (항상 적용): 이미 구현했지만 커밋하지 않은 상태다. `test_color_positions_are_balanced`로 검증한다.
- **`reset(options={"randomize": True})`** 일 때 아래를 무작위로 바꾼다.
  - **조명**: 밝기 배율 0.6~1.4. 색온도는 따뜻함부터 차가움까지 RGB 배율로 준다(예: R 0.85~1.15, B 0.85~1.15). 헤드라이트와 방향광 모두 적용한다.
  - **책상**: 기본 나무색 주변에서 RGB 각 ±0.15(0~1로 자름)
  - **바닥**: 회색 0.3~0.8
  - **공 색**: 기본값에서 각 채널 ±0.05
  - 모든 값은 `self.np_random`에서 뽑는다. 다음 reset 때 randomize가 꺼져 있으면 기본값으로 되돌린다.
- **장면 구성** (`options={"scene": ...}` 또는 randomize와 함께 쓰는 `scene_mix`):
  - `"three"`: 기본. 공 3개가 책상 위에 있다.
  - `"two"`: 명령한 색이 아닌 공 하나를 작업 공간 밖(책상 아래 보이지 않는 위치)으로 치운다. 성공 판정과 보상에서는 그 공을 무시한다.
  - `"prebinned"`: 명령한 색이 아닌 공 하나를 통 안에 넣은 상태로 시작한다(연속 명령 상황). 성공 판정에서 기존 keep_scene과 같은 규칙(리셋 때 통에 있던 공은 무시)을 쓴다.
- **테스트**
  - randomize를 켜면 같은 seed에서는 렌더링이 같고, seed가 다르면 조명과 책상 색이 달라진다.
  - randomize를 끄면 기본값으로 돌아온다.
  - `two`와 `prebinned` 장면에서 명령한 색 공이 책상 위에 있다.
  - `prebinned` 장면에서 미리 통에 있던 공 때문에 성공이 막히지 않는다.
  - 시연 스크립트 성공률이 유지된다(장면별 각 10개 중 9개 이상).
- **눈으로 확인**: 무작위화한 위쪽·손목 렌더 6장을 `outputs/plan5/`에 저장하고 직접 확인한다. 공 색이 서로 구분되는지 본다.

## Task 2: 네거티브 시연 모드 (`expert/scripted.py`)

- **`ScriptedExpert(..., wrong_approach=True)`**
  1. 실행 경로는 먼저 **명령하지 않은 색 공 하나**(무작위) 위의 공 위 자세(PRE_Z)로 간다.
  2. 그 자리에서 0.3~0.6초 멈춘다.
  3. 명령한 색 공 위로 옮겨 간 뒤 기존 단계(하강, 닫기 등)를 이어 간다.
- **라벨**: 잘못된 공으로 접근하고 멈추는 동안의 라벨은 기존 correction 모드와 같은 규칙을 쓴다. 현재 관절값에서 명령한 색 공 위 자세 쪽으로, 속도 제한 안에서 한 스텝 가는 행동이다. 그리퍼 라벨은 궤적 값을 따른다. 명령한 색 공으로 옮겨 가는 구간부터는 실행과 라벨이 같다.
- 잘못된 공에 다가갈 때 그리퍼가 공을 건드리지 않도록 PRE_Z 높이를 유지한다.
- 장면에 명령한 색 이외의 공이 없으면(two 장면에서 치운 경우 등) correction 모드로 대신한다.
- **테스트**
  - 잘못된 공 접근 구간에서 라벨이 실행 행동보다 명령한 색 공 위 자세에 항상 더 가깝거나 같다.
  - 성공률이 20개 중 19개 이상이다.
  - 실행 경로가 실제로 잘못된 공 근처(수평 3cm 이내)까지 간다.
  - 기본 모드 출력은 바뀌지 않는다.

## Task 3: 수집 옵션 + 수집

- `data/collect.py`
  - `--randomize`: 모든 에피소드에 시각 무작위화를 켠다.
  - `--mode-mix`: 에피소드마다 실행 방식을 고른다(기본 / correction / wrong_approach를 1/3씩). 같은 배치의 명령 3종은 같은 장면을 쓰되, 실행 방식은 에피소드마다 독립적으로 고른다.
  - `--scene-mix`: 배치마다 장면을 고른다(three 60%, two 20%, prebinned 20%). `--same-layout`과 함께 쓴다. two와 prebinned 장면에서는 책상 위에 남은 색에 대해서만 명령을 만든다.
  - 기존 옵션의 동작은 바꾸지 않는다.
- 수집 명령:

  `python -m data.collect --same-layout --randomize --mode-mix --scene-mix --repo-id local/so101_ballsort_sim_v5 --root data/so101_ballsort_sim_v5 --n-per-color 100 --seed 300000`

  배치당 명령 수가 장면에 따라 2~3개이므로, 색별 100개를 채울 때까지 배치를 계속 늘린다.
